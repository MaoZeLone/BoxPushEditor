# 交互物

一只交互物是一份定义资产。规则写在定义上，关卡里摆的是它的实例。同一种定义共用规则。某一关里的一只，只改定义上允许重载的那几项。

官方内容在 `Content/Data`。没配贴图的物体不画图。

## 现成的几种

- **普通箱：** 推一次走一格。
- **滑动箱：** 沿推动方向滑到被挡住。
- **返回箱：** 这一步播完回到被推之前的格子。家格被人或其他箱子占着就留在新格。
- **目标：** 要推上去的箱子都在目标上才算过关。人站在目标上不算。
- **踏板：** 箱子压上去会变成按下，推走会弹起。
- **地形：** 地板、墙、空洞不是交互物。地板能走，墙和空洞不能走。

## 逻辑组件

定义上的逻辑组件，有就生效，同类最多一条。格子怎么走只看这些组件，不看当前状态。

| 组件 | 作用 |
| --- | --- |
| Blocking | 这格有实体。挡人、挡推可以分开关。墙用地形，不挂这个。目标和踏板不挂，所以箱子可以叠上去 |
| Pushable | 人朝它再走一步就尝试推。可推箱子至少要有 Blocking 和 Pushable。一次推几格默认是 1 |
| Slide | 叠在 Pushable 上。有它就不再看「一次推几格」，沿这次的方向滑到停。遇箱停下打开时，前方是另一只箱子就停 |
| Return | 叠在 Pushable 上。记下这一步开始时的格子。延迟几步为 0 时，这一步表现完立刻回家 |
| Goal | 胜利点。上面叠了类型匹配、并且带 Pushable 的实例，这一格算占满。所有计入胜利的目标都占满才过关 |
| Pedal | 被匹配类型压上时发「压上事件」，离开时发「离开事件」。事件 Id 留给开门用 |
| Trigger | 格子传感器。有它，进入和离开的转移条件才生效。不挡人、不挡推，也不算胜利。接受的类型空着时，玩家和任意交互物都算 |

目标的「要叠上的类型」、踏板和传感器的「接受的类型」用 Gameplay Tag。空着的传感器谁都能踩到。

压上事件、离开事件留空就不发。别的物体要跟着变，转移条件里的事件名要和这里填的一致。

## 状态

定义的 State 分类下是两张表：状态、转移。

一个状态有进入、停留、离开，这一行自己带表现：

- **可视度：** 显或隐。
- **贴图：** 换成指定图。
- **挡路：** 改这一状态下挡不挡人、挡不挡推。门打开时把挡路关掉，就是用这个，不是靠改逻辑组件。

一条转移写从哪个状态、什么条件、到哪个状态，这一行也带自己的表现。表现跟着这条转移走，不另开一张表。

条件有三种：

- **On Event：** 本关有人发出同名事件。目标和踏板的压上、离开，以及状态动作里的 Fire Event，都会发这种事件。
- **Begin Overlap / End Overlap：** 有人进入或离开这一格。物体上要有 Trigger，这两条才生效。

状态上的 Fire Event 会把事件名广播给本关所有实例，各自用自己的转移表对名字。

踏板按下、弹起，是自己听压上和离开，切到对应状态。事件名要在踏板组件和转移上两边都写上。
