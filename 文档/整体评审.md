## 做对的

- 对局权威在 `UBoxBoard` / `UBoxGridSim`，画面跟 `ABoxMatchWorld`。编辑器试玩走同一套模拟，没有第二套推箱子。
- 试玩标了「不写档」。`SettleWin` 在 `bPlaytest` 时不调用 `RecordClear`。
- 普通 / 滑动 / 返回箱子是同一份定义上的组件差，不是三个 Actor 类。
- 编辑器试玩前会跑 `Validate`，有 Error 开不了。
- 局外已经有主菜单、选关、设置音量；对局 HUD 有暂停和胜利。选关、下一关、解锁按总表 `SortOrder`。编辑器左边列表现在也按这个排。

方向对。问题是：**几份设计互相打架，而且有的能力和运行时接不上。**

## 2. 设计上的问题

### 表现只剩 2D，缺图仍按名字猜

交互物 DA 上的 3D 树、`UTileVisual`、`DefaultCameraAsset` 和单独的 2D DA 已经从代码里拿掉。图配在原来的交互物、角色、地形 DA 上。没配表现组件时，仍按种类用 Kenney 默认裁切。

镜头是 `BoxPlayCamera` 里写死的正交参数，`ABoxMatchWorld` 直接用。`UPlayerMoveLogic::StepDuration` 默认 0.15，对局不读，步时以 `ABoxMatchWorld::StepDuration` 为准。

### 事件卖成已接，运行时只打日志

格子模拟会切踏板 `Pressed` / `Released`，`FireEvent` 推进 `FiredEvents`。`ABoxMatchWorld` 只 `UE_LOG`。没有订户，不会去改别的实例。

系统文档说 3 天不做开门，这可以。不能同时在官方备注和校验里把它写成可用功能。数据层在卖运行时没有的能力。

### 角色链路文档是 Tag，按键是原始键

功能清单写的是：键 → `InputTag` → ActionSet → Relation → 格子模拟。  
`ABoxPlayerCharacter::PollMoveKeys` 用 `IsInputKeyDown` 直接 `EnqueueMove`。Enhanced Input 的 Move 绑定已经拿掉。`CanPerform` 仍看 ActionSet 和 Relation，所以能力行还能挡住走、撤、重开。

键位和「按 Tag 发指令」已经不是一条链。编辑器试玩又是另一套：视口里自己记 `HeldMoveKeys`，再推进同一个 `EnqueueMove`。模拟共享是对的，输入分了两套，改键位要改两处。

### 星级写在系统里，存档只有通关

系统：通关按 `ParMoves` 给 1–3 星，存最少步和星级。  
`FBoxLevelRecord` 只有 `bCleared`。`RecordClear` 只把这一位置真。选关能锁下一关，没有星、没有步数成绩。

这是产品承诺没做完，不是隐藏 bug。演示时不要说有星级。

### 实例重载：新字段仍要模拟里有人读

编辑器按 `InstanceOverride` 扫属性，键名是属性名。对局取值也用同一属性名（`bBlocksPlayer`、`bBlocksPush`、`bStopOnBox`、`Steps`、`DelayMoves`、`RequiredType`、`AcceptType`）。  
`EventId` 能在面板里改、能存，对局不读。再加一个只带元数据的字段，面板会出现，试玩仍忽略，直到模拟里有函数按这个属性名去取。

## 3. 实现上的问题

### 每次加载官方箱子都拆掉状态机

`UInteractableDef::PostLoad` 对 `Box_Normal` / `Box_Slide` / `Box_Return` 调用 `KeepSingleIdleState`：清空 `States` / `Transitions`，只留一个 Idle。没有「只迁一次」。在官方箱子上加的状态，重开编辑器就没了。

目标和踏板不走这条，所以它们的 Occupied / Pressed 还在。三种箱子和另外两种定义，加载规则不一样。

迁移可以做，必须一次性。种子只走 `ApplyOfficialDefaults`。

### 关卡装不上仍当完整关开打

`UBoxBoard::InitFromLevel`：找不到 `UInteractableDef` 只打 Warning 然后 `continue`，最后 `return true`。棋盘可以少箱子、少目标，胜负按残局算。

`ABoxGameMode::StartPlay` 不看 `StartLevel` 的返回值，也不跑 `Validate`。编辑器试玩有 Error 会拦，正式选关、PIE 不拦。

缺定义应失败初始化。正式开局和试玩用同一道门。

### 返回箱回家失败仍清计时

`UBoxGridSim::FlushImmediateReturns`：家格被占就不动箱子，但 `MovesUntilReturn = -1` 一定写。这一步没回家，之后也不会再试。

只在箱子真的回到家之后清计时。

### 踏板「玩家也能踩」是死分支

`RefreshOccupancyStates`：`Accept` 无效时玩家站上去算压下。`UPedalLogic::PostLoad` 在无效时写成 `Type.Interactable.Box`。加载之后 Accept 总有效，玩家踩踏板不会发生。

不要在 `PostLoad` 里填默认。要玩家可踩，就让默认值表达这件事，而不是加载时改掉。

### 一步有两份时钟

`ABoxMatchWorld::StepDuration`（0.36）管玩家插值和这一步何时结束。`ABoxInteractableActor::InterpDuration`（0.36，私有）自己 Tick 箱子。改 MatchWorld 的时长，箱子和人会脱节。

步时只留 MatchWorld 一处，箱子跟它。

### 加载路径会改 DA、会钉死对象

`UBoxActionSet::PostLoad` 发现有 Undo 没有 Redo 就 `AddGrantedAction`，里面 `MarkPackageDirty()`。打开工程可能把能力表弄脏。`AddGrantedAction` / `ResetGrantedActions` 只要被调用就标脏，包括种子。

`BoxSokobanSheet::CropTexture`、Kenney UI 字体、若干 fallback DA：`AddToRoot()`，没有对应的拆根。这是钉到进程结束，不是缓存。

`InteractableSpriteDef` / `PlayerSpriteDef` / `TileSpriteDef` 为了官方裁图 include `Match/BoxSokobanSheet.h`。数据资产编译绑到对局表现。裁图常量应放在数据或独立头，Match 只拿来画。

### PrimaryAssetId 两套规则

`InteractableDef`、`InteractableSpriteDef`、`LevelData` 用逻辑 Id（空了才用资产名）。`UBoxActionSet` 用 `GetFName()`（`DA_*`）。Asset Manager 按一种规则登记、按另一种规则查，会对不上。

全项目一种：逻辑 Id 或资产名，`GetPrimaryAssetId` 和 Lookup 一致。

## 4. 编辑器

### 非试玩也吞掉 WASD

`FBoxLevelViewportClient::InputKey`：方向键一律 `return true`，先交给 `NotePlayMoveKey`。没在试玩时这些键不再交给视口相机。

只在 `IsPlaying()` 时消费移动键。

### 改关卡、改顺序都不走引擎事务

`FBoxEditScope` 自己快照再 `MarkPackageDirty()`，没有 `Modify()` / `FScopedTransaction`。关卡列表上移下移同样只改 `DT_LevelCatalog` 的 `SortOrder` 再标脏。引擎 Undo 和这套栈不是一回事。

笔试可以保留自己的笔刷撤销，但要说清楚：Ctrl+Z 是关卡编辑栈，不是 Content Browser 那套。改 DataTable 前至少 `Modify()`。

### 上移下移按总表邻居，不按当前筛出来的那一列

搜索框滤掉中间关时，按钮仍和总表里真正的上一关、下一关对调，不是和眼前这一列的邻居对调。没进总表的关排在下面，没有按钮。这和「未上架也能移」一致：未上架只要有总表行就能移。

演示时先清空搜索再调顺序，避免看起来跳关。

### 试玩和设计说的 PIE 不是一条路

编辑器试玩用预览关卡，停了回到本窗口，这比设计里的 PIE 更适合改关。和正式局的差别要能讲清楚：模拟同一套；输入、相机、HUD 不是同一套。正式局的暂停和胜利界面，试玩里没有。

## 演示前先处理的

按扣分，不按工作量：

1. `PostLoad` 不要再每次清空官方箱子的状态。这是打开工程就丢数据。
2. 正式开局和试玩一样：校验失败或 `InitFromLevel` 丢了定义，就不要开打。
3. 返回箱只有回家成功才清 `MovesUntilReturn`。
4. 口头口径改成和代码一致：画面是 2D 精灵；踏板只切状态，不开门；存档只有通关，没有星级；试玩在编辑器里，不进 PIE。

第 4 条不改代码也能少被追问。前 3 条是实现错误。
