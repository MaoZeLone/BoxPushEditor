# 代码评审（原则问题）

当前结论以 [整体评审](整体评审.md) 为准。本文里「打开调色板就改 DA」已经过时。

笔试口径：3 天、产品级推箱子 + 关卡编辑器。不追求优雅。下面只列**会让面试官扣分的原则问题**：契约和实现不一致、静默失败、加载/只读路径改资产、权威数据和表现双份、编辑器输入所有权。风格、命名、文件长短本身不在这里。

---

## 先说做对的

- 对局权威在 `UBoxBoard` / `UBoxGridSim`，表现跟 `ABoxMatchWorld`。编辑器试玩走同一套，没有再写一套格子求解。
- 编辑器试玩有 `bPlaytest` / 「不写档」，通关不走 `RecordClear`。
- 交互物用逻辑组件 + 状态表，普通 / 滑动 / 返回箱子是组件差，不是三个互抄的类。
- 校验在编辑器里能拦住带 Error 的关卡开试玩。

这些方向对。问题出在：**文档和 DA 承诺的能力，运行时经常没接上或接错了。**

---

## 1. 加载和只读路径改正式资产

**原则：** `PostLoad`、打开面板、扫资源，都不是用户在编辑。这些路径不该改内容、不该 `MarkPackageDirty()`。

### 每次加载官方箱子都会拆掉状态机

`UInteractableDef::PostLoad` 对 `Box_Normal` / `Box_Slide` / `Box_Return` 调用 `KeepSingleIdleState`：清空 `States` / `Transitions`，只留一个 Idle。没有版本号、没有「只迁一次」。策划在官方箱子上加的状态，重开编辑器就没了。

迁移可以做；必须一次性、可检测、不要每次 `PostLoad` 都重写。种子只该走显式脚本 / `ApplyOfficialDefaults`。

### 打开内容浏览器会改 Player / Interactable DA

`FBoxLevelEditor::RebuildPalette` 在扫描时补 Type、改显示名、调 `SeedOfficialOverrideFlags()`，然后 `MarkPackageDirty()`。只是打开编辑器就会把包弄脏，SCM 噪声，也说不清「谁改了我的 DA」。

面板是读路径。修数据用校验、Fixup 按钮或 Python 种子。

同类：`UBoxActionSet::PostLoad`、若干 `ApplyOfficialDefaults` / `AddGrantedAction` 在运行时模块里 `MarkPackageDirty()`。加载旧资产会永久弄脏包。

---

## 2. 失败被吃掉，模拟仍当成功

**原则：** 关卡装不上、实例丢了，不能 Warning 完继续当完整关。

### `InitFromLevel` 跳过坏实例仍 `return true`

找不到 `UInteractableDef` 只打 Warning 然后 `continue`。`ABoxGameMode::StartPlay` 也不看 `StartLevel` 的返回值。权威棋盘可以少箱子、少目标，胜负仍按残局算。

缺定义应失败初始化；GameMode 不能在 `false` 上继续。

### 运行时根本不跑 `Validate`

`ULevelData::Validate` 有。编辑器试玩看 `bHasErrors`。PIE / 进包 `StartPlay` 不调校验。校验只对工具有效，对真正玩关无效。和上一条叠在一起：坏关能开、还能少实例。

`StartLevel` 应对 Error 直接拒绝（或目录里就不给进）。

### 返回箱：回家失败仍清计时

`UBoxGridSim::FlushImmediateReturns`：家格被占就不动箱子，但 **`MovesUntilReturn = -1` 一定写**。回家失败等于永远不回。

只在真正回家成功后清计时；失败应保留或按规则重试。

## 3. 数据契约和运行时不是同一套

**原则：** DA / 校验 / 备注写了什么，运行时就要按那个做，或者明确标成未接。不要半套真、半套摆设。

### `VisualComps`、相机、3D 地形是死数据，玩的是 2D + Kenney 兜底

- `FBoxLevelInstance` 写表现和逻辑都从交互物 DA 读。运行时 `ABoxInteractableActor` 只建 `UInteractableSpriteDef`，没有 `Def->VisualComps`。缺 2D DA 时按 `DefinitionId` 字符串裁 Kenney。
- `UPlayerDef::DefaultCameraAsset` 校验当 Error 缺了不行；对局相机是 `ABoxMatchWorld` 里写死的正交 `SpriteView`。
- `UTileVisual` 还在；地面/墙走 `UTileSpriteDef` + Kenney 矩形。

面试官改 3D DA 或相机资产，画面不变。三套来源（3D DA、2D DA、硬编码图集）会漂。

玩哪套就让哪套成为唯一表现源。另一套删掉，或明确只给编辑器预览。缺图不要按英文 Id 猜箱子。

### `FireEvent` / 踏板开门：配得上，跑起来是 log

`ExecuteInteractableStateActions` 把 `FireEvent` 推进数组。`ABoxMatchWorld` 只 `UE_LOG`。没有订户、不会 `ApplyEvent` 到别的实例。官方踏板备注写「Put door events on Pressed OnEnter」。校验还检查 `FireEvent` 要有 `EventId`。

技术策划写了 3 天内不开门、发出去没有订户。代码和备注仍像已接好。对笔试这是假契约：数据层和校验在卖一个运行时没有的功能。

要么运行时真分发，要么从官方备注/校验里拿掉，DA 上标 stub。

### 踏板「Accept 无效则玩家也算」是死分支

`RefreshOccupancyStates`：`bPlayerCounts = !Accept.IsValid()`。`UPedalLogic::PostLoad` 无效就写成 `Type.Interactable.Box`。加载后 Accept 总有效，玩家踩踏板这条永远不走。注释和代码打架。

不要在 `PostLoad` 里填默认，或者删掉玩家计数分支。

### PrimaryAssetId 半套用逻辑 Id，半套用 `DA_` 文件名

`InteractableDef` / `InteractableSpriteDef` / `LevelData` 用 `DefinitionId`。`TileSpriteDef` / `PlayerSpriteDef` / `TileVisual` / `ActionSet` 用 `GetFName()`（`DA_*`）。Asset Manager 按一种规则扫、按另一种规则查，会对不上。种子时已经出现过 `InteractableSpriteDef:DA_Box_Normal` vs 对象真实 id `Box_Normal`。

全项目一种：逻辑 Id 或路径，Lookup 和 `GetPrimaryAssetId` 一致。

### 2D 配套规则不统一

交互物：每个 Id 一份 `DA_<Id>`，关卡校验缺了只 **Warn**（拦不住试玩）。地形/角色 2D 是单例。3D `DA_Player` 和 2D `DA_Player` 短名相同、目录不同。

「2D 可配」要有同一套身份和校验强度。缺 2D 若不允许空画，应是 Error。

## 4. 权威状态有两份钟、两份「官方表」

**原则：** 一步棋一个时钟。官方清单一份。

`ABoxMatchWorld::StepDuration`（0.36，可改）驱动玩家插值和阶段结束。`ABoxInteractableActor::InterpDuration`（0.36，私有、不相连）自己 Tick 插值箱子。改 MatchWorld 时长，箱子中途会和玩家脱节。

`UPlayerMoveLogic::StepDuration` 默认 0.15，对局也不读。角色数据里的步时是摆设。

官方 Id 列表散在 `InteractableDef.cpp`、`InteractableSpriteDef::ApplyOfficialDefaults`、Actor 的 Kenney 分支、编辑器中文名表。加一个箱子要改多处，漏一处就调色板/图/兜底不一致。

步时只放一处（MatchWorld 或 PlayerDef，另一处跟）。官方目录一张表或 Primary Asset 列表，种子和兜底都读它。

## 5. 编辑器：输入所有权和事务

**原则：** 工具只在自己的模式里吃按键。改 UObject 走引擎事务。

### 非试玩也吞掉 WASD

`FBoxLevelViewportClient::InputKey`：方向键一律 `return true`。`HandlePlayKey` 在 `!bPlaying` 时是空操作，键已经不给轨道相机。编辑模式 WASD 失效。

只在 `IsPlaying()` 时消费移动键，否则交给 `FEditorViewportClient::InputKey`。

### 关卡撤销绕开 `FScopedTransaction` / `Modify()`

`FBoxEditScope` 自己快照 + `MarkPackageDirty()`。引擎 Undo 和这套栈不是一回事。笔试不要求完美事务，但「改 DataAsset 却不用 `Modify()`」是 UE 编辑器的基本契约。

用 `FScopedTransaction` + `CurrentLevel->Modify()`，或写明这是隔离栈并关掉这些包的编辑器 Undo。

### 涂格子跟 Tick 抢、跟按键回调抢

视口 `Tick` 里 `World->Tick`，再轮询鼠标涂抹/点选；`InputKey` / `CapturedMouseMove` 里还有一份。焦点、抬起、连涂容易双写或丢抬起。

涂抹的 begin/move/end 只放输入回调。预览世界的 Tick 交给 Preview Scene 的策略。

`FBoxLevelEditor.cpp` 三千多行：目录、调色板、详情、笔刷、校验、试玩、撤销、存盘挤在一起。不是「文件太长」，是没法单测、改一处容易踩另一处。笔试可以挤，职责边界仍应能指出来。

试玩输入是 WASD 直送到 `EnqueueMove`，进包走 Enhanced Input。模拟层共享是对的；输入再分叉，键位和能力检查会漂。

## 6. 模块方向反了，所有权不清

**原则：** Data 不该 include 对局表现。`UObject` 缓存不该 `AddToRoot` 钉到进程死。

`InteractableSpriteDef` / `PlayerSpriteDef` / `TileSpriteDef` / `PlayerDef` 为了官方矩形去 include `Match/BoxSokobanSheet.h`。数据资产编译、cook 绑到 Kenney 裁图。表现常量应在 Data 或独立共享头，Match 只消费。

`BoxSokobanSheet::CropTexture`、若干 fallback DA、Kenney UI 字体：`AddToRoot()` + 静态表。没有对等的拆根。这是进程级钉死，不是缓存策略。

`AbilitySystem/` 下没有 ASC/GA。`GetBlockAndCancelTags` 没有调用方；`CanPerform` 只用 `CanActivate`。`PlayerDef` 注释还写对齐 Lyra PawnData。面试官会问 GAS 在哪。标签当能力开关可以，就不要摆一套关系映射 API 装作接了。

## 面试时最可能被问的五条

1. 打开编辑器 / `PostLoad` 会不会改 DA？  
2. 缺定义的关卡会不会当成完整关开打？校验拦的是编辑器还是 GameMode？  
3. 改 `VisualComps` 或相机 DA，为什么画面不变？2D 丢了为什么还能画出箱子？  
4. `FireEvent` 配了之后谁在听？  
5. 非试玩时 WASD 为什么转不了视口？关卡撤销走的是哪套 Undo？

## 刻意不写的

- 函数能不能再拆、命名好不好听、要不要接口  
- 中文直接写在 C++ 里（笔试可以；真正的问题是官方中文名写死在编辑器，和「表驱动」打架，已归进调色板）  
- 没有自动化单测（3 天可以没有；有校验总比没有强，但校验没进运行时是原则问题，上面有）  
- 编辑器试玩不写存档（这条是对的）
