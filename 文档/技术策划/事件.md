# 事件 · 技术策划案

格子模拟先发事件，订户以后再接。3 天内踏板只切状态，不开门、不做任务编辑器。

---

## 职责

**管**

- 约定模拟事件名字
- 踏板 `EventId` 作为以后订阅的键

**不管**

- 任务图、成就、关卡内事件编辑器
- 用事件决定能不能推（那是 Blocking + 地形）

两条通道不要混：

1. **模拟事件**（`Pushed` 等）：切交互物 `CurrentState`
2. **关卡事件**（`UPedalLogic.EventId`）：压下后通知世界（门、连锁）。现在发出去但没有订户

---

## 功能

| 功能 | 状态 |
|---|---|
| 模拟事件切 States | 有 |
| Goal / 踏板 Pressed、Released | 有（占用变化时发） |
| 按 EventId 订户开门 | **未做** |

---

## 参数

### 模拟事件名（写在 `States.EnterOn`）

| 名字 | 来源 |
|---|---|
| `Pushed` | 普通推 |
| `SlideStart` | 滑行推 |
| `Blocked` | 推了但没动 |
| `Arrived` | 落定 |
| `Returned` | 回程开始 |
| `Pressed` | Goal 被占 / 踏板压下 |
| `Released` | 离开 |

### 踏板

| 参数 | 默认 | 说明 |
|---|---|---|
| `EventId` | 空 | 非空时，压下应发给事件系统。现只切 Pressed |
| `AcceptFolder` | `Box` | 谁能压 |

没有事件总表。以后订户按名字订阅，不要先做任务编辑器。
