# 交互物数据

UE 5.5.4 · 推箱子  
关卡实例挂一份定义资产。这一份 DA 回答：**这种东西长什么样、有哪些逻辑、会进哪些状态。**  
官方要出哪五份、优先级见 [配置表](配置表.md)。

不做 `DT_Interactable`，不做 `VisualId`，不挂 State Tree。表现和逻辑都是这份 DA 上的组件数组；状态是自己列的名字，不是引擎状态树资产。

```
FBoxLevelInstance.Definition     TSoftObjectPtr<UInteractableDef>
        │
        ▼
DA_Box_Normal 等 (UInteractableDef)
        ├─ VisualComps[]   表现组件，扁平数组 + ParentId 成树
        ├─ LogicComps[]    逻辑组件，有就生效
        └─ States[]        自己定义的状态，运行时 FSM
```

路径：`/Game/Interactables/DA_Box_Normal` …  
形态：`UPrimaryDataAsset`  
Primary Asset Type：`InteractableDef`  
`DefinitionId` 写在 DA 上，创建后不改，且等于资产名去掉 `DA_` 前缀。

地形（空 / 地板 / 墙）不进交互物。墙不是交互物。

---

## 1. 原则

- **关卡里是实例，资产里是定义。** 换「往回箱子」只换实例上的 `Definition`，或改那份 DA 的数组，不改 C++ Actor 类。
- **一种定义一份 DA。** 策划复制 `DA_Box_Normal` → `DA_Box_Heavy`，增删组件即可。
- **表现、逻辑两套数组，不要混。** Mesh / 特效 / 挂点只进 `VisualComps`；能不能推、算不算目标只进 `LogicComps`。
- **有就生效，不要 `bEnabled`。** 数组里没有 Pushable，就不能推。不要再在 DA 上预留一排空组件再打勾。
- **格子规则先算完，再切自己的状态。** 逻辑组件回答这一步结果；`States` 只描述实例现在处于哪个表现阶段。
- **不挂 State Tree，不查 VisualId。** 表现树由 `VisualComps` 生成；状态由 `States` 列出。

和关卡总表的差别：关卡需要 `SortOrder` / `bListed`，所以用 DataTable 挂 DA。交互物没有顺序、没有下架，Asset Manager + 软引用就够。

---

## 2. 资产：`UInteractableDef`

**形态：** `UPrimaryDataAsset`  
**资产名：** `DA_<DefinitionId>`  
**谁读写：** 内容浏览器、关卡编辑器调色板  
**谁只读：** 对局、校验、格子模拟、刷表现

`GetPrimaryAssetId()` 返回 `(InteractableDef, DefinitionId)`。

### 2.1 显示

| 字段 | 类型 | 说明 |
|---|---|---|
| `DefinitionId` | `FName` | 创建后不改。例：`Box_Normal`。必须与资产名 `DA_Box_Normal` 对应 |
| `DisplayName` | `FText` | 编辑器调色板、细节面板 |
| `Folder` | `FName` | 调色板分类：`Box` / `Target` / `Pedal` |
| `DesignerNote` | `FString` | 仅编辑器 |

### 2.2 两套组件 + 状态

| 字段 | 类型 | 说明 |
|---|---|---|
| `VisualComps` | `TArray<UInteractableVisualComp*>`（Instanced） | 表现。`ParentId` 指同一数组里另一条的 `CompId` |
| `LogicComps` | `TArray<UInteractableLogicComp*>`（Instanced） | 逻辑。同类最多一条 |
| `States` | `TArray<FInteractableStateDef>` | 本定义允许的状态。恰好一个 `bDefault` |
| `DefaultState` | 由 `States` 里 `bDefault==true` 的那条决定 | 不要再单独存一份容易漂的字段 |

细节面板里对 Instanced 数组点 Add，选子类。新机制 = 新组件类丢进数组，不加新 DA 类。

## 3. 表现组件 `VisualComps`

场景里同一个交互物 Actor。生成时按数组建 SceneComponent 树：`ParentId` 为空则挂 Actor Root；否则挂到同 Id 的那个组件上。

基类 `UInteractableVisualComp : UObject`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `CompId` | `FName` | 本 DA 内唯一。例：`Root`、`Body`、`Glow` |
| `ParentId` | `FName` | 父节点 `CompId`。空 = 挂到 Actor |
| `RelativeLocation` | `FVector` | 相对父 |
| `RelativeRotation` | `FRotator` | 相对父 |
| `RelativeScale` | `FVector` | 默认 (1,1,1) |
| `VisibleInStates` | `TArray<FName>` | 空 = 所有状态都显示；有值则只在这些 `StateId` 下显示 |

先做这些子类：

| 类 | 额外字段 | 用途 |
|---|---|---|
| `UVisualMeshComp` | `Mesh`、`MaterialOverride` | 箱体、目标垫、踏板板面 |
| `UVisualEmptyComp` | 无 | 只当挂点，方便下面再挂子节点 |
| `UVisualNiagaraComp` | `Niagara` | 滑行拖尾、压下闪光。可空，空则跳过 |
| `UVisualAudioComp` | `Sound` | 推动 / 压下音。可空则跳过 |

数组是扁平的，树靠 `ParentId`，不要做成递归 `Children` 数组（Details 里不好编）。

规则：

1. `CompId` 本 DA 内唯一、非空。
2. `ParentId` 要么空，要么能在本数组找到，且不能指向自己。
3. 不能成环。
4. 父必须排在子前面不是硬性要求；生成时先建全部再 Attach。
5. 允许多个 Root（都挂 Actor）。

普通箱子最小树：

```
Root (Empty)  ParentId=None
 └ Body (Mesh)  ParentId=Root
```

目标可以再挂一个只在 `Occupied` 显示的 Glow。没有模型时 `Mesh` 留空，运行时用引擎方块占位。

## 4. 逻辑组件 `LogicComps`

基类 `UInteractableLogicComp : UObject`，带 `CompId`（本 DA 内唯一，调试用）。  
格子模拟只读这一数组。同类（同一 UClass）最多一条，多了报错。

### `UBlockingLogic` 阻挡

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `bBlocksPlayer` | `bool` | true | 挡住角色 |
| `bBlocksPush` | `bool` | true | 挡住被推的箱子 |

墙用地形，不走这个组件。箱子挂一条。目标、踏板不挂，所以箱子可以叠在上面。

### `UPushableLogic` 可推动

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `Steps` | `int32` | 1 | 每次推动走几格 |

角色面向它再走一步时尝试推动。前方必须可站，且没有另一个带 Blocking 的实例。`Steps>1` 仍是一次输入里连走，中途碰到阻挡就停。校验统计「箱子数」看的是有没有这个组件。

### `USlideLogic` 推到底

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `bStopOnBox` | `bool` | true | 前方是另一只箱子则停 |

必须同时有 `UPushableLogic`。有 Slide 时忽略 `Steps`，沿本次方向滑到停。模拟结束后发事件 `SlideStart`。

### `UReturnLogic` 往回

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `DelayMoves` | `int32` | 0 | 再过几步才回去。0 = 这次移动的表现结束立刻回 |

必须同时有 `UPushableLogic`。记录的「原位」是这一步开始时的 `Cell`。撤销先撤玩家操作，再清这个回程。模拟结束后发事件 `Returned`。

### `UGoalLogic` 目标

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `RequiredFolder` | `FName` | `Box` | 谁停在上面算入胜。空 = 任意带 Pushable 的实例 |

校验：带 `UGoalLogic` 的实例数 = 带 `UPushableLogic` 的实例数，且 ≥ 1。同一格叠 Goal + Pushable 合法。

### `UPedalLogic` 踏板

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `AcceptFolder` | `FName` | `Box` | 谁能压。空 = 箱子或玩家都能压 |
| `EventId` | `FName` | None | 压下时发给事件系统。没有事件表就只切状态 |

踏板不挂 Blocking。先做出压下状态，开门之类以后再接 `EventId`。

## 5. 自己的状态 `States`

不是 State Tree 资产，不是全局枚举。每种定义自己列允许进哪些状态。运行时实例上只有一个 `CurrentState`（FName），对上这里的 `StateId`。

`FInteractableStateDef`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `StateId` | `FName` | 本 DA 内唯一。例：`Idle`、`Moving`、`Sliding`、`Returning`、`Pressed` |
| `DisplayName` | `FText` | 调试、细节面板 |
| `bDefault` | `bool` | 出生、复位用。全表恰好一条为 true |
| `EnterOn` | `TArray<FName>` | 哪些**模拟事件**切进这个状态 |

模拟事件由格子层发出，不由表现层发出。先定这些名字：

| 事件 | 何时 |
|---|---|
| `Pushed` | 箱子被推走了一格（或 Steps 连走开始） |
| `Arrived` | 这一步移动结束，停在新格子 |
| `Blocked` | 试图推但没动 |
| `SlideStart` | 开始沿方向滑 |
| `Returned` | 开始回原位 |
| `Pressed` | 踏板被压下 |
| `Released` | 踏板弹起 |

同一事件不要写在两条状态的 `EnterOn` 里。没写到的事件保持当前状态。

表现组件的 `VisibleInStates` 对着这些 `StateId`。逻辑组件**不**读 `CurrentState` 来决定能不能推。

格子模拟仍然不看「前面是不是用状态挡住」。墙、Blocking、可站格才是玩法真相。

## 6. 官方五份 DA（先做这些）

| 资产 | Folder | LogicComps | States（默认 / EnterOn） |
|---|---|---|---|
| `DA_Box_Normal` | Box | Blocking + Pushable(Steps=1) | `Idle`(Arrived, Blocked)；`Moving`(Pushed) |
| `DA_Box_Slide` | Box | Blocking + Pushable + Slide | 上表 + `Sliding`(SlideStart) |
| `DA_Box_Return` | Box | Blocking + Pushable + Return | 上表 + `Returning`(Returned) |
| `DA_Target` | Target | Goal | `Idle`(默认)；`Occupied`(有箱子叠上时由模拟发 `Pressed`/`Released` 也可先只用 Idle) |
| `DA_Pedal` | Pedal | Pedal | `Idle`(Released)；`Pressed`(Pressed) |

表现：五份都先 `Root(Empty) → Body(Mesh)`，Mesh 可空。目标、踏板以后再加 Glow 子节点，`VisibleInStates` 绑 `Occupied` / `Pressed`。

不要为三种箱子写三个 Actor 类。场景里都是同一个交互物 Actor：按 `VisualComps` 建树，按 `LogicComps` 注册到格子，按 `States` 切 `CurrentState`。

编辑器调色板：Asset Registry 查 `UInteractableDef`，按 `Folder` 分组。新种类 = 新建一份 DA，不用改总表。

## 7. 关卡实例怎么指过来

`FBoxLevelInstance` 不存行名，存软引用：

| 字段 | 类型 | 说明 |
|---|---|---|
| `InstanceId` | `FName` | 本关内唯一 |
| `Definition` | `TSoftObjectPtr<UInteractableDef>` | 指向定义 DA |
| `Cell` | `FIntPoint` | 格子 |
| `YawSteps` | `int32` | 0–3 |

不要再留 `DefinitionId` 字符串，也不要在实例上覆写组件数组。查逻辑、刷表现，都先解析 `Definition`。

同一格允许叠多个实例（目标 + 箱子）。同一格不允许两个 Blocking，由校验保证。

运行时实例另有一份不进关卡资产的数据：`CurrentState`、当前格子（对局中可变）、回程原位。关卡 DA 只存出生。

## 8. 边界

| 数据 | 放哪 |
|---|---|
| 这格有什么 | `FBoxLevelInstance` |
| 能不能推、算不算目标 | `LogicComps` |
| Mesh / 挂点 / 特效 / 音效 | `VisualComps`（树） |
| 现在是 Idle 还是 Sliding | `States` + 运行时 `CurrentState` |
| 格子能不能走 | `ULevelData.Cells` |
| 踏板触发后干什么 | `UPedalLogic.EventId` → [系统 · 事件](../设计/系统.md)；三天内只切状态 |
| 地形用地砖还是墙模 | `DA_TileVisual`，见 [配置表](配置表.md) |
| 有哪些关 | 仍是 `DT_LevelCatalog` |

---

## 9. 校验

关卡侧（替换原来的 `Box_` 前缀）：

- `Definition` 非空，能加载为 `UInteractableDef`
- 带 `UPushableLogic` 的实例数 = 带 `UGoalLogic` 的实例数，且 ≥ 1
- 同一格若有两个 `UBlockingLogic`，报错
- 带 Pedal / Goal 的实例所在格必须可站

定义 DA 自身：

- `DefinitionId` 非空，与 Primary Asset Name 一致
- `VisualComps`：`CompId` 唯一；`ParentId` 合法、无环
- `LogicComps`：同类最多一条；有 Slide / Return 必须有 Pushable
- `States`：`StateId` 唯一；恰好一个 `bDefault`；`EnterOn` 的事件名不重复占用；`VisibleInStates` 里的名字必须能在 `States` 里找到

---

## 10. 和 MCP / 编辑器的关系

和单关一样，用 `set_editor_property` 写字段。Instanced 数组在编辑器里 Add 子类；MCP 创建官方五份时按类名 NewObject 再 Add。  
关卡编辑器画板只写实例上的 `Definition` 和 `Cell`，不编组件树。
