# 关卡数据

UE 5.5.4 · 推箱子  
本文只定两份资产：**总关卡表**、**单关 DataAsset**。交互物、角色见 [交互物数据](交互物数据.md)、[角色数据](角色数据.md)；要配哪些表见 [配置表](配置表.md)。地形表现是 `DA_TileVisual`，不进本资产。

编辑器读写这两份。运行时只读。玩家存档不写回这里。

```
DT_LevelCatalog          有哪些关、顺不顺序、上不上架
        │ LevelAsset
        ▼
DA_Level_XX (ULevelData) 这一关的地形、出生点、实例
        │ Definition
        ▼
DA_Box_Normal 等 (UInteractableDef)  箱子 / 目标 / 踏板怎么动
```

路径约定：

- 总表：`/Game/Data/DT_LevelCatalog`
- 单关：`/Game/Levels/BuiltIn/DA_Level_01` …
- 交互物定义：`/Game/Interactables/DA_Box_Normal` …（见 [交互物数据](交互物数据.md)）
- 角色定义：`/Game/Characters/DA_Player`（见 [角色数据](角色数据.md)）。关卡不引用它，只写 `PlayerSpawn`

---

## 1. 总关卡表 `DT_LevelCatalog`

**形态：** DataTable  
**行结构：** `FLevelCatalogRow`  
**谁读：** 选关 UI、解锁、编辑器关卡列表、新建关时挂表  
**不存：** 格子、实例、推荐步数、显示名

选关只扫这张表。内容永远去 `LevelAsset`。

### 1.1 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 行名 | `FName` | 是 | 与 `LevelId` 相同，方便查表 |
| `LevelId` | `FName` | 是 | 存档键。创建后不改。例：`LV_01` |
| `LevelAsset` | `TSoftObjectPtr<ULevelData>` | 是 | 指向该关 DA |
| `SortOrder` | `int32` | 是 | 官方顺序，越小越前。允许空号，按数值排 |
| `bListed` | `bool` | 是 | `true` 才进选关。半成品为 `false` |

### 1.2 规则

1. 表内 `LevelId` 不重复。
2. `LevelId` 必须等于 `ULevelData.LevelId`，也必须等于该行行名。
3. 解锁不写在本表。列出 `bListed==true` 的行，按 `SortOrder` 升序；第 0 关默认解锁，其后一关是否可进看存档里上一关是否通关。
4. 新建关：创建 `ULevelData`，同时加一行，`bListed=false`。
5. 校验通过后才把 `bListed` 设为 `true`。校验失败仍可保存 DA，但选关看不到。
6. 删除关：先下架（`bListed=false`），再决定是否删 DA。不要只删资产留一行空指针。

### 1.3 运行时怎么用

选关：过滤 `bListed`，按 `SortOrder` 排序，软加载 `LevelAsset` 取 `DisplayName`、`ParMoves` 做卡片。  
进关：用 `LevelId` 异步加载 `LevelAsset`，交给关卡管理器。  
下一关：当前 `SortOrder` 之后、仍为 `bListed` 的最小一行。

## 2. 单关 `ULevelData`

**形态：** `UPrimaryDataAsset`  
**资产名：** `DA_Level_XX`  
**谁读写：** 关卡编辑器（双击打开的就是它）  
**谁只读：** 对局、试玩 PIE、选关卡片上的显示名和推荐步数

一关一份。不要把 12 关塞进一张 DataTable 的一行里。

### 2.1 显示

| 字段 | 类型 | 说明 |
|---|---|---|
| `LevelId` | `FName` | 与总表同一套 Id |
| `DisplayName` | `FText` | 选关、HUD |
| `DesignerNote` | `FString` | 仅编辑器。这一关在教什么 |

### 2.2 规则数字

| 字段 | 类型 | 范围 | 说明 |
|---|---|---|---|
| `ParMoves` | `int32` | ≥1 | 推荐步数。步数 ≤ 此值为 3 星；≤ 1.5 倍为 2 星；通关为 1 星 |
| `Width` | `int32` | 5–20 | 格子宽 |
| `Height` | `int32` | 5–20 | 格子高 |

改 `Width` / `Height`：多出来的格子填 `Floor`；裁掉的格子丢弃。若裁到 `PlayerSpawn` 或任一实例，先确认再裁。

### 2.3 地形

程序化刷 Mesh 的输入，不是手摆墙 Actor。

| 字段 | 类型 | 说明 |
|---|---|---|
| `Cells` | `TArray<ETerrainCell>` | 长度必须 = `Width * Height`，行优先：`Index = Y * Width + X` |

```
ETerrainCell
    Empty    关外 / 空洞，不能站、不能推入
    Floor    地板，可站、可推入
    Wall     墙，不可进入
```

目标**不**进这个枚举。目标是交互物实例。箱子压在目标上时，该格地形仍是 `Floor`，上面叠目标实例和箱子实例，状态不会丢。

`Empty` 与关外：地图矩形内也可以有空洞（例如中间挖空）。越出 `Width/Height` 一律视为不可走，不必在数组外再存一圈。

### 2.4 角色出生

| 字段 | 类型 | 说明 |
|---|---|---|
| `PlayerSpawn` | `FIntPoint` | 恰好 1 个。角色不做成交互物，也不进 `Instances` |

出生格的地形必须是 `Floor`（或将来允许的可站地形，不含 `Wall` / `Empty`）。

### 2.5 实例

关卡里每一个可配置物：箱子、目标、踏板，以及以后新加的交互物。

| 字段 | 类型 | 说明 |
|---|---|---|
| `Instances` | `TArray<FBoxLevelInstance>` | 本关全部实例 |

`FBoxLevelInstance`（不能叫 `FLevelInstance`，会和引擎的 `ALevelInstance` 撞名）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `InstanceId` | `FName` | 本关内唯一。撤销栈、事件、调试指名用这个，不用下标 |
| `Definition` | `TSoftObjectPtr<UInteractableDef>` | 指向交互物定义 DA。例：`DA_Box_Normal`、`DA_Box_Return`、`DA_Box_Slide`、`DA_Target`、`DA_Pedal` |
| `Cell` | `FIntPoint` | 格子坐标，原点左上或左下在实现里统一，推荐 X 向右、Y 向前 |
| `YawSteps` | `int32` | 0–3，每步 90°。推箱子用不到，先留 |

同一格允许叠多个实例（目标 + 箱子）。同一格不允许两个阻挡型实例，这条由校验和定义 DA 共同保证，不在本结构里写死类型。

实例不带模型、不带组件列表。表现和逻辑都去 `Definition` 那份 DA。

## 3. 两份资产的边界

| 数据 | 放哪 |
|---|---|
| 有哪些关、顺序、上架 | 总表 |
| 显示名、推荐步数、格子、实例 | 单关 DA |
| 通关、最少步数、星级 | `USaveGame`，键为 `LevelId` |
| 箱子怎么推、踏板怎么触发 | 交互物定义 DA 的 `LogicComps` |
| 交互物 Mesh / 挂点 | 交互物定义 DA 的 `VisualComps` |
| 人怎么走、怎么推、长什么样 | `DA_Player`（GameMode 引用，关卡不引用） |
| 当前试玩是否写档 | 流程层，不进资产 |

## 4. 校验（对着这两份资产跑）

错误则不能 `bListed=true`，不能试玩。DA 仍可保存。

1. `LevelId` 非空；与总表行名一致；总表内不重复。
2. `LevelAsset` 能加载，且其中 `LevelId` 与行一致。
3. `Width`、`Height` 在 5–20；`Cells.Num() == Width * Height`。
4. `PlayerSpawn` 在矩形内，且该格为 `Floor`。
5. 每个实例：`InstanceId` 本关唯一；`Cell` 在矩形内；所在格不是 `Wall` / `Empty`；`Definition` 能加载为 `UInteractableDef`。
6. 玩家数量按出生点计，必须为 1。
7. 定义 DA 的 `LogicComps` 里带 `UPushableLogic` 的实例数 = 带 `UGoalLogic` 的实例数，且 ≥ 1。

警告（能上架，编辑器标黄）：

- 最外圈存在非 `Wall` 的格子（角色可能走出去，若项目不允许走出则升为错误）
- `ParMoves < 1`
- `DesignerNote` 为空

---

## 5. 新建关默认值

总表加一行：`LevelId=LV_Custom_N`，`SortOrder=当前最大+1`，`bListed=false`。

DA 默认 `8×8`：最外圈 `Wall`，内部 `Floor`；`PlayerSpawn=(2,3)`；实例两个——`DA_Box_Normal` 在 `(3,3)`，`DA_Target` 在 `(5,3)`。这样打开就能过校验里「1 人 1 箱 1 目标」，可以立刻试玩。

---

## 6. 和 MCP / 编辑器的关系

总表适合用 DataTable 的 JSON 整表写入（`fill_data_table_from_json_string`）。  
单关是 DataAsset，用 `set_editor_property` 改标量；`Cells` 和 `Instances` 由关卡编辑器画板写，不走手填 JSON。

编辑器保存顺序：先写 DA，跑校验，再改总表该行的 `bListed`。
