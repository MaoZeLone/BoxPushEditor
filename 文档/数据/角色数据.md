# 角色数据

UE 5.5.4 · 推箱子  
本文定玩家定义。角色不扩展：没有角色表、没有多职业、关卡里不选人。  
官方四份 DA + IMC 见 [配置表](配置表.md)。

关卡只存出生格 `PlayerSpawn`。人怎么生成、怎么输入、有哪些操作，在 `UPlayerDef`；**整份角色定义对齐 OpenWorldActEditor 的 PawnData，不抄交互物。不上 GAS。**

```
ABoxGameMode.DefaultPlayerDef
    │
    ▼
DA_Player (UPlayerDef)                 对齐 PawnData 形状，不授 GA
        ├─ PawnClass
        ├─ InputConfig              →  DA_InputConfig_Player
        ├─ ActionSet                →  DA_ActionSet_Player
        └─ TagRelationshipMapping   →  DA_AbilityTagRelationships_Player
```

路径：

- `/Game/Characters/DA_Player`
- `/Game/Characters/Input/DA_InputConfig_Player`
- `/Game/Characters/DA_ActionSet_Player`
- `/Game/Characters/DA_AbilityTagRelationships_Player`

`UPlayerDef` 是 `UPrimaryDataAsset`，Primary Asset Type：`PlayerDef`。  
官方只做这一套。角色**不是**交互物，不进 `Instances`。

---

## 1. 从那边拿走什么、不拿什么

OpenWorldActEditor：`AERGameMode.DefaultPawnData` → `UERPawnData`（PawnClass + InputConfig + AbilitySets + Camera）。Character 是薄壳。按键只发 Tag；技能生命周期在 GA；别人看到的状态是 `State.*` / `Status.*` Tag。

拿走：

- **PawnData 形状。** `UPlayerDef` = PawnClass + InputConfig + ActionSet + TagRelationshipMapping。
- **独立 InputConfig。** IMC + Native 表，`InputAction ↔ GameplayTag`。
- **操作填行，不授 GA。** AbilitySet 那张「生成时 Give 到 ASC」换成 `UBoxActionSet.GrantedActions[]`。有没有某能力 = 表里有没有那一行。
- **状态是 Tag，不是交互物那份 `FInteractableStateDef`。** 走路授 `State.Walking`，推动授 `State.Pushing`；Idle = 这两条都不在。
- **能不能做某操作，先查表有没有行，再查 Relation。** 对齐 Lyra `ULyraAbilityTagRelationshipMapping`：身上有 `Status.StepLocked` 时挡 `Ability.Move` / `Push` / `Undo`。
- **Actor 是薄壳。** `ABoxPlayerCharacter` 不写「能不能推」。Mesh / 弹簧臂在 Pawn 类上。

不拿：

| 那边 | 这边 |
|---|---|
| GAS / ASC / GA / GE / AttributeSet | 不上。不 `GiveToAbilitySystem`，不往身上堆 `Ability.*` |
| Experience / WorldSettings / GameFeature | 关卡已经是 `ULevelData` |
| Gameplay Cameras / CameraAsset | 弹簧臂在 Character 上，不接 CameraAsset |
| 冲刺 / 体力 / 跳 / F 键交互 | 推箱子用不到 |
| 多份 PawnData 换人 | 角色不改变 |
| 交互物 `States[]` + `EnterOn` | 只给箱子 / 踏板用，人不用 |

---

## 2. 原则

- **关卡里是格子，资产里是人。**
- **输入、状态走 3C 那条链。** 不要把交互物的 VisualComps / LogicComps / States[] 套到人身上。
- **按键只发 Tag。** Native 表对到 `InputTag`；ActionSet 行再对到 `Ability.*`。
- **格子能不能落看地形和 Blocking。** 这一步能不能发，看 ActionSet 行 + Relation，不看交互物状态表。

---

## 3. 资产：`UPlayerDef`

**形态：** `UPrimaryDataAsset`  
**资产名：** `DA_Player`  
`GetPrimaryAssetId()` 返回 `(PlayerDef, PlayerId)`。

### 3.1 显示与生成

| 字段 | 类型 | 说明 |
|---|---|---|
| `PlayerId` | `FName` | 官方 `Player`。必须与资产名 `DA_Player` 对应 |
| `DisplayName` | `FText` | |
| `DesignerNote` | `FString` | 仅编辑器 |
| `PawnClass` | `TSubclassOf<APawn>` | 默认 `ABoxPlayerCharacter` |

### 3.2 3C 挂接（对齐 PawnData）

| 字段 | 类型 | 说明 |
|---|---|---|
| `InputConfig` | `TObjectPtr<UBoxInputConfig>` | 独立 DA，不要把 IMC 内嵌进 PlayerDef |
| `ActionSet` | `TObjectPtr<UBoxActionSet>` | 这个角色有哪些操作。官方挂一份，行要填满 |
| `TagRelationshipMapping` | `TObjectPtr<UBoxAbilityTagRelationshipMapping>` | 当前能不能发。独立 DA |

不要在这份 DA 上再放 `States[]`、`VisualComps`、`LogicComps`、`FPlayerInputBind`、`AbilitySets`。

---

## 4. 表现

Mesh、弹簧臂在 `ABoxPlayerCharacter` 上，和 OpenWorldActEditor 的 Character 薄壳一样。关卡编辑器预览用 PawnClass 默认外观刷在 `PlayerSpawn`。动画读 `State.Walking` / `State.Pushing` / `Status.StepLocked`。

---

## 5. 走和推

不是交互物那种 Instanced 逻辑组件。

- **走：** Native `InputTag.Move`，对局模拟消费。
- **推：** ActionSet 里有 `Ability.Push` 这一行，且朝 `Folder=Box` 且有 Pushable 的格子再走一步即推。箱子滑不滑仍看交互物逻辑。Push 不绑键。
- **相机：** Character 上的弹簧臂，不接 CameraAsset。

撤销 / 重开 / 暂停走 Native Tag，对局流程消费。

---

## 6. 输入 `UBoxInputConfig`

独立 DataAsset，对齐 `UERInputConfig` 的 Native 一半。路径 `/Game/Characters/Input/DA_InputConfig_Player`。

| 字段 | 说明 |
|---|---|
| `DefaultMappingContext` | IMC。键位写在 IMC 上 |
| `NativeInputActions` | Move / Undo / Restart / Pause。`FBoxInputAction`：Action + InputTag |

没有 Ability 输入表。操作是否存在看 ActionSet，不看 InputConfig。

查法：`FindNativeInputActionForTag`。配表用 `AddNativeInputAction(Action, TagName)`。

官方 Native Tag：

| Tag | 谁消费 |
|---|---|
| `InputTag.Move` | 对局格子模拟 |
| `InputTag.Undo` | 对局流程 |
| `InputTag.Restart` | 对局流程 |
| `InputTag.Pause` | 对局流程 / UI |

---

## 7. 操作表 `UBoxActionSet`

对齐 AbilitySet 的「填行」，没有 AbilityClass / GE / AttributeSet。路径 `/Game/Characters/DA_ActionSet_Player`。Primary Asset Type：`ActionSet`。

一行 `FBoxGrantedAction`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `AbilityTag` | `FGameplayTag`（Category `Ability`） | 操作身份。Relation 按这个查 |
| `InputTag` | `FGameplayTag`（Category `InputTag`） | 对到 InputConfig。空 = 不绑键 |

有没有这个能力 = `GrantedActions` 里有没有这一行。**不要把 `Ability.*` 拷到角色 OwnedTags。**

查法：`HasGranted` / `FindByAbilityTag` / `FindByInputTag`。  
配表用 `AddGrantedAction(AbilityTag, InputTag)`；官方用 `ApplyOfficialDefaults`。

官方行：

| AbilityTag | InputTag |
|---|---|
| `Ability.Move` | `InputTag.Move` |
| `Ability.Push` | 空 |
| `Ability.Undo` | `InputTag.Undo` |
| `Ability.Restart` | `InputTag.Restart` |
| `Ability.Pause` | `InputTag.Pause` |

---

## 8. 状态 / Relation Tag

三套 Tag，不要混：

| 前缀 | 干什么 |
|---|---|
| `InputTag.*` | 按键身份。InputConfig 用 |
| `Ability.*` | 操作身份。写在 ActionSet 行上，Relation 表用。不是键，也不授到身上 |
| `State.*` / `Status.*` | 身上现在有什么。动画读；Relation 表挡操作 |

对齐 Lyra `ULyraAbilityTagRelationshipMapping`。这边落成 `DA_AbilityTagRelationships_Player`，挂在 `PlayerDef.TagRelationshipMapping`。

一行关系：

| 字段 | 含义 |
|---|---|
| `AbilityTag` | 这条规则管哪个操作，如 `Ability.Move` |
| `ActivationRequiredTags` | 身上必须有，才允许开 |
| `ActivationBlockedTags` | 身上有任意一条，就禁止开 |
| `AbilityTagsToBlock` | 这个操作进行中，挡住哪些操作 |
| `AbilityTagsToCancel` | 这个操作进行中，取消哪些操作 |

查法：`PlayerDef.CanPerform(Ability.Move, OwnerTags)` = ActionSet 有行 **并且** Relation 允许。Native 走格子前也走这条，不必等 GA。

官方行：

| 操作 | ActivationBlockedTags |
|---|---|
| `Ability.Move` | `Status.StepLocked` |
| `Ability.Push` | `Status.StepLocked` |
| `Ability.Undo` | `Status.StepLocked` |
| `Ability.Restart` | `Status.StepLocked` |

`Ability.Pause` 不进 Relation 表，随时能开（仍要 ActionSet 有行）。

身上现在有什么（只这些进 `ABoxPlayerCharacter.OwnedTags`）：

| Tag | 何时在 |
|---|---|
| `State.Walking` | 走进邻格、没推箱子 |
| `State.Pushing` | 这一步带着箱子走 |
| `Status.StepLocked` | 这一步表现还没播完 |

Idle = 没有 `State.Walking` 也没有 `State.Pushing`。不要做 `State.Idle`。

格子能不能落看地形和 Blocking。这一步能不能发，看 ActionSet + Relation。不要用 Tag 判断前面是不是墙。交互物继续用自己的 `States[]`。

---

## 9. 运行时怎么接

```
ABoxGameMode.DefaultPlayerDef → DA_Player
  Character.ApplyPlayerDef     → 记下 Def，清空 OwnedTags（不拷 Ability.*）
  InputConfig → 绑 IMC
    Native InputTag.Move → ActionSet 对到 Ability.Move → CanPerform → 格子
    Native Undo / Restart → 同上 → 流程
    Pause 不查 StepLocked
  ActionSet.GrantedActions[] → 有没有某操作
  TagRelationshipMapping → 这一步能不能发

格子成功
  授 State.Walking 或 State.Pushing
  授 Status.StepLocked，表现结束再撤
```

关卡编辑器预览用 `PawnClass` 刷在 `PlayerSpawn`。存档不存角色定义。

---

## 10. 边界

| 数据 | 放哪 |
|---|---|
| 人出生在哪一格 | `ULevelData.PlayerSpawn` |
| Pawn 类、输入、操作表、Relation | `DA_Player` |
| 键位 | IMC |
| Action ↔ InputTag | `DA_InputConfig_Player` |
| 这个角色有哪些操作 | `DA_ActionSet_Player` 的 `GrantedActions[]` |
| 当前能不能发 | `DA_AbilityTagRelationships_Player` + 身上的 State/Status |
| 现在在走还是在推 | Character `OwnedTags` 上的 `State.*` / `Status.*` |
| 箱子怎么被推 | 交互物 `LogicComps` |
| 箱子 Idle / Sliding | 交互物 `States[]` |

---

## 11. 校验

- `PlayerId` 非空，资产名 = `DA_` + PlayerId
- `PawnClass`、`InputConfig`、`ActionSet`、`TagRelationshipMapping` 非空
- IMC 非空；Native 必须有 `InputTag.Move` / `Undo` / `Restart`（Pause 可缺）
- ActionSet 必须有 `Ability.Move` / `Undo` / `Restart`（Pause / Push 官方有，Push 可无键）
- ActionSet 行若写了 InputTag，InputConfig.Native 必须有对应行
- 关卡：恰好一个可站的 `PlayerSpawn`
