# 系统

UE 5.5.4 · 推箱子  
数据已经另文定完（[关卡](../数据/关卡数据.md) / [交互物](../数据/交互物数据.md) / [角色](../数据/角色数据.md)）。要配哪些表见 [配置表](../数据/配置表.md)。每个系统的职责、功能、参数见 [技术策划](../技术策划/README.md)。本文只回答开发记录里那句：**会有哪些系统。**

系统是会写代码、会在运行时或编辑器里干活的东西。DataAsset 本身不算系统。

原则（从开发记录来）：

- 数据结构做好，工具层少做
- 交互物组件化，再自己做状态机，不挂 State Tree
- 角色不扩展，不上 GAS
- 游戏体验和编辑器分开；编辑器不进包
- 逻辑格子先改完，表现再跟

                              │ 开局 / 重开 / 撤销 / 胜利
                              ▼

                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
                 地图查询   交互物运行时  事件
                    │         │

编辑器不进这条链。它读写同一份 `ULevelData`，预览复用程序化地形，试玩把当前关塞给流程管理器走 PIE。

## 1. 运行时

按开发记录里点名的，加上玩法缺了就跑不起来的。

### 1.1 地图管理器

开发记录：「去获取相关的数据，前面、后面、各种的。」

进关时加载 `ULevelData`，之后谁问格子都找它。

| 管 | 不管 |
|---|---|
| 这一格是空 / 地板 / 墙 | 胜负 |
| 这一格叠了哪些实例 | 撤销栈 |
| 某方向邻格、再前一格 | 刷 Mesh 用哪张模型（那是地形表现表） |
| 可不可站：地形 + `UBlockingLogic` | UI |

运行时格子状态（人在哪、箱子在哪）活在这里，不写回关卡资产。

### 1.2 格子模拟

推箱子的玩法真相。一次有效输入 = 一步。

| 管 | 不管 |
|---|---|
| 四向走；墙忽略 | 插值、动画 |
| 前一格有 `UPushableLogic` 则尝试推 | 角色能不能发这一步（那是 ActionSet + Relation） |
| `USlideLogic` / `UReturnLogic` | 暂停菜单 |
| 全目标是否被占满 | |
| 发出模拟事件：`Pushed` / `Arrived` / `Blocked` / `SlideStart` / `Returned` / `Pressed` / `Released` | |

先改格子，再让表现播。撤销记的是这一步的格子差分，不深拷贝整图。

### 1.3 流程管理器

开发记录分局内、局外。一个入口，两段职责。

**局内**

| 动作 | 做什么 |
|---|---|
| 游戏开始 | 加载关、刷地形、刷实例、刷人，步数清零 |
| 撤回 / 重做 | 步骤记录；先撤玩家操作，再清箱子回程 |
| 重新开始 | 用同一份 `ULevelData` 从头刷，不走选关 |
| 关卡成功 | 全部 Goal 满足 → 按 `ParMoves` 给 1–3 星 → 胜利 UI |

**局外**

| 动作 | 做什么 |
|---|---|
| 选关 | 只扫 `DT_LevelCatalog` 里 `bListed` 的行 |
| 存档 | 通关、最少步、星级；键是 `LevelId` |
| 试玩 | 编辑器塞进来的那一关；**不写档** |

暂停、继续、回选关也走这里。不要在 Character 或箱子 Actor 里写开局/结算。

### 1.4 交互物运行时

开发记录：「其实就是交互物。组件化，然后状态机化。」

场景里同一种 Actor。定义来自 `UInteractableDef`。

1. `VisualComps[]` 生成组件树
2. `LogicComps[]` 注册到地图管理器（能不能推、算不算目标、踏板）
3. `States[]` 接模拟事件，只切 `CurrentState`（表现阶段）

逻辑组件不读 `CurrentState` 来决定能不能推。墙不是交互物。

官方先五种定义：普通箱、推到底、往回、目标、踏板。新种类 = 新 DA + 往数组里丢组件，不加新 Actor 类。

### 1.5 角色 3C

开发记录：「简单的 3C，加上动画，Lyra 的简单框架，能力赋予，按格子走而不是纯线性。」

角色不改变：没有角色表，关卡里不选人。

```
按键 → InputConfig（Tag）
     → ActionSet 有没有这一行
     → Relation 当前能不能发（身上有 Status.StepLocked 就挡住走/推/撤）
     → 格子模拟
     → 授 State.Walking 或 State.Pushing，表现结束再撤 StepLocked
```

Mesh / 弹簧臂在 Character 上。推动差异做在箱子上，不做人的变体。

### 1.6 事件

开发记录：「通过事件去做一些操作。」踏板 `EventId` 走这里。

3 天内：格子模拟发出去，踏板只切 `Pressed` / `Idle`。开门、连锁以后再订户。不要做任务编辑器。

### 1.7 程序化地形

开发记录：「看看有没有资源，能连起来的。」

`Cells[]` → Static Mesh。编辑器预览和正式对局读同一张表现表。换模型只改表，不改关卡数据，也不改规则。

墙的邻接换变体是 P2，可以先同一面墙模。

### 1.8 表现

开发记录：「是否要角色、动画、角色预设。」要，但是薄。

- 人、箱子移动：短插值，逻辑已经落格
- 箱子在目标上：变色或 Glow（`VisibleInStates`）
- 动画：读 `State.Walking` / `State.Pushing`，Idle = 两个都没有
- 四个音：移动、推动、胜利、按钮
- 相机：按本关包围盒居中；弹簧臂在 Character 上

### 1.9 UI

开发记录：「基础开始 UI。」产品级要能进能出，不是一张关卡直接开打。

| 界面 | 内容 |
|---|---|
| 主菜单 | 开始、设置、退出 |
| 选关 | 官方顺序、未通关下一关锁定、星级 |
| 对局 HUD | 步数、暂停 |
| 暂停 | 继续、重开、回选关 |
| 胜利 | 再玩、下一关、回选关 |
| 设置 | 主音量，立刻生效并写档 |

游戏内菜单用 UMG。编辑器面板不是这套。

### 1.10 存档

`USaveGame`。已通关、最少步数、星级。不写回 `ULevelData`。试玩、重开中途退出都不污染进度。

设置里的音量可以写在同一份，也可以另存，不要和关卡资产混。

### 1.11 校验

开发记录：「会有校验。」规则已经写在三份数据文档里。

谁调用：

- 编辑器：保存、上架、试玩前必跑
- 运行时：进关前可再跑一遍；非法关选关列表本来就看不到

校验不是玩法系统，是数据能不能进流程管理器的门。

### 1.12 对象池

开发记录打了问号。12 关、格子 5–20，先直接 Spawn / Destroy。真卡了再补。

## 2. 编辑器

独立 Editor 模块，Slate 资产编辑器，不进包。设计见 [关卡编辑器设计](关卡编辑器设计.md)。这里只把它当成系统，占一行职责。

| 块 | 干什么 |
|---|---|
| 预览 | 视口里刷和运行时同一套 Mesh |
| 笔刷 | 点击单放，按住拖是连续画；橡皮右键 |
| 调色板 | Asset Registry 扫 `UInteractableDef`，按 Folder 分组 |
| 校验面板 | 列出错误；点一条高亮对应格（P1） |
| 试玩 | 校验过 → PIE 走正式 `GM_Play`，停了回到本窗口 |
| 撤回 | 先走 UE 资产 Dirty / Ctrl+Z；笔刷级 Undo 是 P1 |

编辑器不实现第二套推箱子规则。合不合法由校验拦；好不好玩由策划 PIE。

游戏内容和测试内容分开：官方关在 `Content/Levels/BuiltIn/`，试玩请求、半成品不要混进选关表。

## 3. 和数据怎么分

| 数据（已另文） | 系统（本文） |
|---|---|
| `DT_LevelCatalog` / `ULevelData` | 地图管理器读它；选关 UI 扫总表 |
| `UInteractableDef` 组件 + 状态 | 交互物运行时按数组生成、按事件切状态 |
| `UPlayerDef` / Input / ActionSet / Relation | 角色 3C |
| 地形枚举 `Empty/Floor/Wall` + `DA_TileVisual` | 程序化地形 + 地图查询 |
| 存档结构 | 流程管理器局外写；对局不写回关卡 |

关卡只存出生。人怎么走在角色定义；箱子怎么被推在交互物定义。

## 4. 开发记录里点到、但不做成系统的

| 记录里的话 | 落哪 |
|---|---|
| 箱子怎么拓展 | 交互物 DA 增删组件，不新开「箱子系统」 |
| 角色要不要拓展性 / 角色不改变 | 不做成系统 |
| Runtime 数据重载 | 问号。3 天不做热重载 |
| 要不要做任务编辑器 | 不做 |
| 是否要考虑多个包 | 不考虑 |
| 调试进不进包 | 编辑器模块不进包；对局 HUD 的试玩标记可以进 |
| lua / 蓝图写交互物逻辑 | 逻辑组件用 C++ Instanced，不挂脚本 VM |
| stt（State Tree） | 不用，自己的 `States[]` |

## 5. 明确不做（系统级）

- GAS / ASC / GA
- 任务编辑器、成就、排行、计时、死亡
- 游戏内画关、自定义关、关卡分享
- 多角色、换人
- 把玩家登记成交互物
- 每种箱子一个 Actor 类
- 对象池、Mass、World Partition

---

## 6. 建议落地顺序

数据骨架已经有了。系统按这条链接，前面断了后面空转。

1. 地图管理器 + 程序化地形（一关能刷出来）
2. 格子模拟 + 交互物运行时（能推普通箱，能判胜）
3. 角色 3C（按格子走，StepLocked）
4. 流程：开始 / 撤销 / 重开 / 胜利
5. UI + 存档
6. 推到底、往回、踏板（事件先发后接）
7. 关卡编辑器（预览复用第 1 步那套生成）
8. 官方关用编辑器画

D1 用手填的 `ULevelData` 就能玩。D2 把「手填」换成编辑器。D3 用编辑器交 12 关。

排期、每天演示点、已完成项见 [开发规划](开发规划.md)。
