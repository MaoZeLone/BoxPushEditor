# 关卡编辑器 · 大概设计

面向：鸣潮技术策划笔试 / UE 5.5.4  
形态：Slate 资产编辑器（`BoxLevelEditor`），编辑器模块，不进包体  
用户：关卡策划（作者）。玩家只玩运行时流程。

数据字段以 [关卡数据](../数据/关卡数据.md) 为准。本文偏工具交互。和数据文档不一致的，按下面这条：

- 总表是 `DT_LevelCatalog`（DataTable），不是 `DA_LevelCatalog`
- 单关类名 `ULevelData`，资产 `DA_Level_XX`
- 地形只有 `Empty` / `Floor` / `Wall`。目标、箱子是 `Instances` 里的交互物，不进地形枚举
- 预览刷 Mesh：地形读 `DA_TileVisual`；箱子/目标/踏板读各自 `UInteractableDef.VisualComps`；玩家读 `DA_Player.PawnClass`

## 0. 功能定稿

只做下面三块。没写进去的，这 3 天不做。

### 运行时

- 主菜单：开始游戏、设置、退出
- 选关：官方关按解锁顺序排列，未通关的下一关锁定，显示星级
- 对局：四向移动、推箱子、步数、撤销、重开
- 暂停：继续、重开、回选关
- 胜利：再玩、下一关、回选关；步数对比推荐步数给 1–3 星
- 设置：主音量，立刻生效并写入存档
- 存档：已通关、最少步数、星级
- 内容：12 关，全部用本编辑器做出来

### 编辑器（一个 Slate 窗口）

- 双击 `UBoxLevelData` 打开；左侧关卡列表可换关
- 新建：默认一圈墙、1 玩家、1 箱子、1 目标，并挂进官方关表
- 预览场景：按 `DA_TileVisual` 刷出地砖、墙、目标、箱子、玩家模型
- 内容浏览器列出可放置单位，选中后作为当前笔刷；单位定义是登记表，新增单位会同时出现在浏览器和细节里
- 右侧是定制细节面板，随选中项切换，不共用一张通用表：选关卡看关卡字段，选单位看该单位自己的规则和模型，选场景里的实例看坐标
- 笔刷直接点在预览模型上：地板、墙、目标、箱子、玩家、橡皮；另有选择工具，点已放置的单位
- 改宽高时，若会裁掉玩家或箱子，先确认
- 校验：列出错误；点一条，预览里高亮对应格子
- 保存：无错误才上架；有错误可存半成品，选关看不到
- 试玩此关：校验通过后 PIE；不写玩家存档；停止后回到本窗口

### 校验规则（错误，拦住上架和试玩）

- 玩家恰好 1 个
- 箱子数 = 目标数，且至少 1
- 玩家和箱子只能站在地板或目标上
- 宽高在 5–20
- LevelId 不为空，且不与已有关重复

### 表现（运行时和预览共用）

- 格子类型到 Static Mesh 的一张表，编辑器预览和正式游戏读同一份
- 移动有短插值；箱子到达目标时变色
- 四个音效：移动、推动、胜利、按钮
- 相机按本关包围盒居中

### 明确不做

- 游戏内画关、自定义关、关卡分享
- 自定义 Editor Mode、邻接自动换墙、批量校验全部关
- 死亡、计时、成就、排行榜、多语言
- 骨骼动画、Nanite / Lumen 场景、World Partition

## 1. 定位

编辑器只做一件事：在一个窗口里把一关推箱子配成可校验、可试玩、可被运行时直接读取的数据。

运行时（主菜单 / 选关 / 对局 / 结算）只消费这份数据，不提供画关能力。  
制作管线和玩家体验分开，和鸣潮机关、解谜、玩法物件的生产方式一致。

```
策划在编辑器里改 UBoxLevelData
        ↓ 保存 / 校验
Content 里的关卡资产
        ↓ 运行时只读
选关列表 → 对局 Grid → 胜利条件
```

---

## 2. 目标与非目标

功能以第 0 节为准。编辑器是 Editor 模块里的 Slate 资产编辑器，运行时只读数据。

## 3. 使用者与场景

| 场景 | 操作 | 成功标准 |
|---|---|---|
| 新建一关 | 创建 `UBoxLevelData`，设默认尺寸，挂进官方关表 | Content 里多一份资产，选关能扫到 |
| 画布局 | 选笔刷，在网格上拖拽绘制 | 墙 / 地板 / 目标 / 箱 / 玩家所见即所得 |
| 改规则数字 | 填推荐步数、解锁序号、显示名 | 结算星级、选关排序立刻跟这份数据走 |
| 交差前检查 | 点「校验」 | 非法关不能进官方关表 |
| 验证手感 | 点「试玩此关」进 PIE | 不切关卡蓝图、不重编译 |

配置体验按「关卡组同事」来：打开就能画，错误用中文列出来，保存回资产，试玩不丢数据。

## 4. 数据（编辑器和运行时的唯一真相）

资产：`UBoxLevelData : UPrimaryDataAsset`  
官方关目录：`Content/Levels/BuiltIn/`  
关卡总表：`DA_LevelCatalog`（有序列表，指向各关资产）

### 4.1 地形层

| 值 | 含义 | 绘制规则 |
|---|---|---|
| Empty | 关外 / 空洞 | 玩家和箱子不能站上去 |
| Floor | 地板 | 可站、可推入 |
| Wall | 墙 | 不可进入 |
| Target | 目标点 | 可站；箱子停在上面算入胜 |

宽高范围：5–20。改尺寸时多出来的格子填 Floor，裁掉的格子直接丢，裁到玩家/箱子时弹确认。

### 4.2 实体层（和地形分开）

- 玩家出生：恰好 1 个格子
- 箱子：一组坐标，数量必须等于 Target 数

箱子压在 Target 上是合法中间态，所以实体不写进地形枚举，避免「目标被箱子盖掉」。

### 4.3 元数据

| 字段 | 用途 |
|---|---|
| LevelId | 稳定 ID，存档用这个，不用显示名 |
| DisplayName | 选关、HUD |
| SortOrder | 官方解锁顺序 |
| ParMoves | 推荐步数，结算 1–3 星 |
| bListed | 是否进选关表；校验失败时强制 false |
| DesignerNote | 仅编辑器可见，写这一关在教什么 |

运行时进度另存 `USaveGame`（已通关、最少步数、星级），不写回关卡资产。

## 5. 工具形态

关卡长什么样，看 **Level Viewport**，不看 Widget。

Widget（`EUW_BoxLevelEditor`）只是操作台：选资产、笔刷、关卡信息、校验、试玩。  
它画的是数据，不是场景。墙如果是石块模型、箱子如果是木箱模型，色块网格里看不到这些。

视口里放一个预览 Actor：`ABoxLevelPreview`。数据一改，就用和运行时同一套生成逻辑，把格子刷成 Static Mesh。策划盯着视口里的模型改关。

```
EUW 笔刷点一下
    → 改 UBoxLevelData 的某一格
    → ABoxLevelPreview 按表现表重建该格的 Mesh
    → 视口里看到的墙 / 箱 / 地板，和 PIE、正式游戏是同一批模型
```

表现表 `DA_TileVisual`（和关卡数据分开）：

| 格子 | 运行时 / 预览生成 |
|---|---|
| Floor | 地砖 Static Mesh |
| Wall | 墙体 Static Mesh，可按邻接换变体 |
| Target | 地砖 + 目标贴花或标记模型 |
| Box | 箱子 Static Mesh，挂在实体层，不写进地形 |
| Player | 玩家占位模型 |

换模型只改这张表，不改关卡数据，也不改规则。临时美术就用 Engine 方块，但生成路径必须是 Mesh，不能是 UMG 色块。

不另做笔刷编辑器、清单编辑器。关卡总表、资产分类用 UE 默认 Details / Content Browser。  
游戏内菜单和 HUD 才用 UMG。编辑器面板用 EUW，只因为它能改资产、能 PIE。

点哪：

- P0：在视口预览的格子上点（预览 Actor 接收点击，换算成格子坐标再写数据）。小地图色块只做导航，不是主画面。
- 3 天来不及做视口点击时，EUW 里留一张小网格当笔刷落点，但视口必须同步出模型。不能只有小网格。

打开方式（三天内做一种即可）：

1. 在 Content Browser 选中 `UBoxLevelData`，运行 EUW，自动绑定该资产
2. EUW 里用对象选择器换关

保存即 `MarkPackageDirty` + 写回字段。不另做中间草稿格式。

## 6. 界面

主画面是视口里的模型。EUW 贴在旁边，不替代视口。

```
┌─ Level Viewport ──────────────────────┐  ┌─ EUW_BoxLevelEditor ─┐
│                                       │  │ 当前关  [新建][保存]  │
│     [墙模型][墙模型][墙模型]           │  │ 笔刷：地板 墙 目标    │
│     [墙] [地砖] [玩家] [木箱] [墙]     │  │       箱子 玩家 橡皮  │
│     [墙] [地砖] [地砖] [目标] [墙]     │  │ 显示名 / 推荐步数     │
│     [墙模型][墙模型][墙模型]           │  │ 宽高 / 策划备注       │
│                                       │  │ [校验] [试玩此关]     │
│  相机：俯视，可旋转、拉近              │  │ 规范结果（点了高亮）   │
└───────────────────────────────────────┘  └──────────────────────┘
```

视口看到的就是玩家将看到的构图：墙高、箱子是箱子、目标是地上的标记。改一格，对应 Mesh 立刻换，不用进 PIE 才看得到。

### 交互约定

- 左键：当前笔刷落下；按住拖拽连续画
- 右键：橡皮（清实体；地形回到 Floor，关外格子回到 Empty）
- 玩家笔刷：新点落下时，旧出生点清掉（保证全局只有 1 个玩家）
- 箱子笔刷：点在已有箱子上则移除，相当于开关
- 目标 / 墙 / 地板：只改地形，不动实体；若该格有实体且新地形不可站，实体一并清掉并提示
- 改宽高失焦或回车后生效，先预览将裁掉的内容

默认 Details 改二维数组，关卡组无法工作，所以要笔刷。笔刷改的是数据；看到的必须是 `DA_TileVisual` 生成的模型。  
自由摆放、每面墙都是手摆的独特 Actor，不采用。推箱子的玩法真相是格子，模型是这张格子的皮肤。手摆会让校验和 12 关都散掉。

## 7. 内容规范（保存和进表的门槛）

点「校验」、保存、或「试玩」前都跑同一套。结果分错误 / 警告。

### 错误（不能进选关、不能 PIE）

1. 玩家数量 ≠ 1
2. 箱子数量 ≠ 目标数量
3. 箱子数量 < 1
4. 玩家或箱子落在 Empty / Wall 上
5. 宽或高越界
6. LevelId 空，或与已有官方关冲突

### 警告（能玩，但列表里标黄）

1. 最外圈没有墙，角色可能走出去（是否允许走出地图：本项目不允许，升为错误也可）
2. 存在死角箱子位（贴两面墙且不是目标）—— P1，来不及可只做文案提示、不做全自动死角分析
3. 未填推荐步数
4. DesignerNote 为空（提醒这一关的教学意图没写）

失败文案直接写人话，例如：「箱子 3 个，目标 2 个，胜利条件无法达成」。  
P1：点击某条错误，画板高亮对应格子。

`bListed`：存在错误时保存仍可写盘（方便半成品），但关卡总表和运行时选关忽略它。

## 8. 试玩闭环

「试玩此关」不另开一套编辑器 GameMode。

1. 先跑校验，有错误则中止并列出
2. 把当前资产写入 `DA_EditorPlayRequest`（或 GameInstance 的编辑器专用字段）
3. 以 `GM_Play` 启动 PIE
4. 对局读到这份请求后只加载这一关，HUD 标「试玩」
5. 停 PIE 回到 EUW，资产仍打开，未保存修改还在

试玩不写玩家存档，避免策划手感测试污染进度。

## 9. 和运行时的边界

| | 编辑器 | 运行时 |
|---|---|---|
| 谁用 | 策划，在 UE 里 | 玩家，在打包游戏里 |
| 读写 | 读写 `UBoxLevelData` | 只读；进度走 SaveGame |
| 职责 | 生产、规范、预览 | 移动、Undo、胜利、选关、设置 |
| GameMode | 无独立 GM；PIE 复用 `GM_Play` | `GM_Menu` / `GM_Play` |

运行时对局规则（编辑器不重复实现一份）：

- 四向移动；墙忽略；箱子看再前一格，空地或目标则人箱同移
- 逻辑格子先改，表现再插值
- 全部箱子在 Target 上即胜
- Undo 用操作栈，不深拷贝整图

编辑器只保证数据合法。合不合法由第 7 节拦；好不好玩由策划自己 PIE。

## 10. 配置体验原则（给评审看的）

1. **默认能用**：新建关自带一圈墙、一块地板、1 玩家、1 箱、1 目标，校验是绿的，马上能试玩
2. **错误可理解**：不报枚举值，报「少了一个目标」
3. **危险操作可撤**：改尺寸会裁人时先确认；绘制本身用 UE 的资产 Dirty，Ctrl+Z 走编辑器撤销即可（P1 再做笔刷级 Undo）
4. **不切上下文**：视口里看模型，旁边改数据、校验、试玩，不用进 PIE 才第一次看到关卡长什么样
5. **半成品允许保存，不允许上架**：和正式内容管线一致

## 12. 验收（编辑器这一条过不过）

1. 不写代码、只开 UE，能新建一关；视口里看到的是墙 / 箱 / 地砖模型，不是一张色块表
2. 故意做成「两个玩家 / 箱和目标不等」，校验拦住，选关看不到
3. 校验通过后点试玩，PIE 里规则与正式对局一致
4. 停 PIE 后还能继续改同一关
5. 官方 12 关均可在 Content 里打开并用本工具复看

满足以上 5 条，即认为「包含关卡编辑器」交付完成。
